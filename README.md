Документы проекта:

- [BRIEF.md](BRIEF.md) — вопросы, с которых всё началось

- [GDD.md](GDD.md) — дизайн-документ: мир, механики, дорожная карта
- [lore/](lore/) — три проработанных варианта мира, персонажей и сюжета

## Запуск

Все команды выполняются из папки проекта. Если открыл новый терминал, сначала:

```bash
cd /Users/uzicus/Desktop/housegame
```

Затем:

```bash
npm install
npm run dev
```

Открыть http://localhost:5173

```bash
npm run build      # проверка типов и продакшен-сборка в dist/
npm run typecheck  # только проверка типов
```

## Управление

| Действие | Клавиатура и мышь | Геймпад |
|---|---|---|
| Движение | WASD | левый стик |
| Прицел | мышь | правый стик |
| Серия ударов | ЛКМ | X |
| Тяжёлый удар | ПКМ, удержать | Y, удержать |
| Рывок | Пробел | A |

Главное правило боя: **рывок отменяет откат после удара**. На этом строится вся боевая
система, всё остальное это следствия.

## Персонаж

Смотритель это трёхмерная модель, отрендеренная в двумерные спрайты. Сейчас это
серая версия из примитивов, собранная скриптом.

Пересобрать персонажа целиком, рендер плюс упаковка:

```bash
npm run warden
```

Занимает около минуты. Кадры складываются в `.render/warden`, готовый лист
попадает в `public/assets/warden.png`.

Отдельными шагами, если нужно:

```bash
npm run render:warden
npm run pack:warden
```

Подробности и план замены на настоящую модель в [ART_PIPELINE.md](ART_PIPELINE.md).

## Устройство кода

```
src/
  config/GameConfig.ts     все настраиваемые числа, единственный источник правды
  input/                   ввод устройств сводится к одному InputIntent
  core/                    обратная связь: заморозка, тряска, вспышка, цифры урона
  combat/                  попадания по дуге, эффект взмаха, интерфейс цели
  entities/                игрок, манекен, полоса здоровья
  animation/               описание листа кадров и проигрывание анимаций
  scenes/                  загрузка ассетов и тестовая арена
tools/
  blender/                 сборка, свет, позы и рендер персонажа
  pack_sheet.py            упаковка кадров в лист
```

Два правила, на которых держится структура:

1. **Один класс — один файл, одна ответственность.** Игрок не вызывает тряску камеры,
   он сообщает о попадании. Подача остаётся заботой сцены.
2. **Числа не живут в коде поведения.** Ощущение боя настраивается правкой
   `GameConfig.ts`, а не правкой классов.

## Про анимацию

Персонажи анимируются покадрово, но ни один кадр не рисуется руками: их рендерит
Blender с трёхмерной модели. Поверх кадров работает процедурная сочность, заморозка
при попадании, тряска, вспышка, отбрасывание и растяжение спрайта.

Настоящего 3D в браузере нет и не будет: модели превращаются в спрайты заранее.
Подробнее в разделе 2 [GDD.md](GDD.md) и в [ART_PIPELINE.md](ART_PIPELINE.md).
